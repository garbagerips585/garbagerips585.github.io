# Deploying Garbage Rips 585

The site is static. Every page under `public/` is generated by the scripts in
`scripts/` and committed, so there is no build step on the server.

**Host: GitHub Pages.** Repo `garbagerips585/garbagerips585.github.io`, branch
`main`, published by `.github/workflows/pages.yml` on every push.

This file used to describe a Cloudflare Pages deploy. That was never the setup
in use, and following it produced two live copies of the site. Cloudflare is
gone: `functions/` has been deleted along with `/api/latest`, which could only
ever have run there.

---

## How a change reaches the live site

```bash
node scripts/build-all.mjs      # writes everything into public/
python3 scripts/check-build.py  # refuses to pass on a broken build
git add -A && git commit && git push
```

`pages.yml` uploads `public/` and deploys. Nothing else is needed.

`build-all.mjs` runs `check-build.py` as its last step, so a clean run has
already been checked. Run it again by hand if you edited anything afterwards.

---

## The nightly refresh

`.github/workflows/refresh.yml` runs at 07:10 UTC. It re-syncs YouTube and the
card prices, rebuilds, and commits if anything changed.

This is the ONLY freshness mechanism. The site used to layer a live RSS feed
over the committed JSON through a Cloudflare function; GitHub Pages cannot
execute a function, so that fetch was a guaranteed 404 and has been removed. A
new upload appears on the site within a day, or immediately if you run the
workflow by hand from the Actions tab.

## Going live on the real domain

Everything below happens in one commit. Do not do it in pieces.

### 1. Buy the domain

`garbagerips585.com`. It is set in `shared/site.mjs` as `DOMAIN`; if you buy a
different one, change it there first and nowhere else.

### 2. Point DNS at GitHub

At the registrar, for the apex domain, four A records:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

And a CNAME for `www` pointing at `garbagerips585.github.io`.

DNS can take up to 24 hours. Do this first and let it settle.

### 3. Flip one flag and rebuild

```bash
# shared/site.mjs
export const LIVE = true;
```

```bash
node scripts/build-all.mjs
```

That single flag moves every canonical, `og:url`, sitemap entry and JSON-LD url
onto the real domain, turns `robots.txt` from `Disallow: /` into `Allow: /`, and
writes `public/CNAME`.

**`public/CNAME` is generated, not hand-written.** GitHub Pages deployed from an
Actions workflow reads the custom domain from a CNAME file inside the uploaded
artifact, and `pages.yml` uploads `public/` only. Without it the custom domain
setting is dropped on the next deploy and the site silently reverts to the
github.io host. It is written by `build-proto.mjs` when `LIVE` is true and
deleted when it is false, so it cannot drift from the flag.

### 4. Prove the flip landed

```bash
grep -rl "github.io" public/ | grep -v assets   # must return nothing
head -3 public/robots.txt                        # must say Allow: /
cat public/CNAME                                 # must be your domain
python3 scripts/check-build.py                   # must pass
```

The first of these is not optional. Seven hand-maintained pages once kept the
staging host through a flip because only `index.html` was in the rewrite list,
which would have had the sitemap and the pages disagreeing about where the site
lives. `videos.html` and `playlists.html` are in that list now, but the grep is
what proves it rather than the intention.

**The flip has been rehearsed twice on 14 August 2026, the second time after
the playlist pages and the whole day's changes landed.** The second run:
34 of 34 builders, ZERO files anywhere under public/ referencing the staging
host, 420 sitemap urls all on the real domain including the 21 playlist pages,
every one resolving to a file, CNAME written and robots.txt open.

The first run, earlier the same day, checked two things the second did not:
no noindex page appears in the sitemap, and every canonical matches its own
path. Three canonicals point at a directory (`/pokemon/`, `/sets/`, `/games/`)
rather than at `index.html`, which is deliberate.

Rehearsing matters here because this path runs exactly once. It has been broken
before and the failure was invisible until the flip: `build-proto.mjs` called
`basename()` without importing it, inside the branch that only executes when
there is a staging url to rewrite. Re-rehearse in a scratch copy after any
change to `shared/site.mjs`, `build-proto.mjs` or the builders, rather than
finding out on the day.

### 5. Push, then set the domain in GitHub

Push, wait for the Actions run to go green, then in the repo:
**Settings → Pages → Custom domain**, enter the domain, save, and tick
**Enforce HTTPS** once the certificate is issued (it can take an hour).

### 6. Search Console

Add the property at <https://search.google.com/search-console>, verify by DNS
TXT record, and submit `https://<domain>/sitemap.xml`.

Do this AFTER the flip. Submitting while `robots.txt` still says `Disallow: /`
teaches Google the site is closed.

---

## Rolling back

Set `LIVE = false`, run `build-all.mjs`, push. Canonicals return to the staging
host, `robots.txt` closes, and `CNAME` is deleted. Remove the custom domain in
Settings → Pages as well, or GitHub will keep serving it.

---

## What is NOT automated

- Buying the domain and the DNS records.
- The custom domain and HTTPS settings in the GitHub UI.
- Search Console verification.
- `YT_API_KEY`. Local runs read `.env`, which is gitignored and must never be
  committed. The nightly workflow reads it from repo secrets.
